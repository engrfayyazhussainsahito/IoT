Randomness & Entropy on Embedded Hardware

Identify weak or absent TRNG sources on cheap microcontrollers.

35 min read Level: MS foundation → advanced Status: Full lesson

1. Introduction

Every cryptographic guarantee in this course rests on an assumption that keys are unpredictable. On embedded hardware, that assumption is far shakier than most engineers realize — cheap microcontrollers frequently lack a genuine hardware random-number source entirely.

2. Learning Outcomes

By the end of this lesson you will be able to:

  • Identify weak or absent TRNG sources on cheap microcontrollers.
  • Explain historical randomness failures that broke device identity.

3. Prerequisites

Week 0 foundations, plus Weeks 0–2 of this course.

4. Core Concepts

A True Random Number Generator (TRNG) harvests physical entropy (thermal noise, jitter between independent oscillators) and, done correctly, produces genuinely unpredictable output. A Pseudo-Random Number Generator (PRNG) deterministically expands a seed into a longer stream that looks random but is fully determined by that seed — if the seed is guessable, so is everything the PRNG produces.

The most dangerous failure mode is boot-time entropy starvation: a device that needs random numbers very early in boot (for example, to generate a session key immediately after powering on) may not yet have accumulated enough environmental noise to seed a PRNG safely, especially if it lacks a hardware TRNG and relies on software entropy sources like timing jitter that need time to accumulate.

7. Mathematical / Formal Foundations

If a device's effective entropy at key-generation time is only, say, 20 bits (due to a limited or predictable seed source) instead of the intended 128 bits, the resulting key space shrinks from 2^128 possibilities to roughly 2^20 — over a million times weaker, and potentially brute-forceable in seconds to minutes depending on the attack.

8. Practical Examples

Worked example: a device without a hardware TRNG seeds its PRNG using only the current timestamp and a fixed serial number at first boot. If the timestamp resolution is coarse (seconds) and the serial number is sequential across a manufacturing batch, many devices in the same batch, powered on around the same time, can end up with substantially overlapping or predictable "random" keys.

9. Code / Worked Example

ENTROPY SOURCE AUDIT
[ ] Does this chip have a dedicated hardware TRNG?
[ ] If not, what software entropy sources are used (timing jitter,
    uninitialized RAM, radio noise)?
[ ] At what point in boot are cryptographic keys first generated?
[ ] Is there a guarantee that sufficient entropy has accumulated
    BEFORE that point, or could key generation race the entropy pool?
[ ] Are unique per-device values (not just serial numbers) mixed
    into the seed to avoid batch-wide correlation?

10. Security Perspective

Weak randomness is one of the few vulnerability classes that can silently defeat otherwise-perfect cryptography — the algorithm, key size, and protocol can all be textbook-correct, and the system is still broken if the "random" key was predictable.

11. Industry Perspective

Modern secure microcontrollers increasingly ship a certified hardware TRNG as a baseline feature specifically because this failure class has caused enough real-world incidents that chip vendors now treat it as a checkbox requirement for security-marketed silicon.

12. Research Perspective

Large-scale internet scans have historically found batches of devices sharing identical or highly correlated cryptographic keys, traced back to exactly this boot-time entropy problem — a well-documented and still-recurring research finding across device categories.

13. Case Study

A widely cited research finding scanned millions of devices and found a meaningful fraction shared RSA keys or had factorable keys due to weak randomness at generation time — directly traceable to embedded devices generating keys before sufficient entropy had accumulated.

14. Common Misconceptions

  • "Any pseudo-random function is fine as long as the algorithm is strong." — A strong PRNG algorithm with a weak or predictable seed still produces predictable output.
  • "If the chip doesn't advertise a TRNG, software entropy sources are just as good." — Software-only entropy sources are often weaker and slower to accumulate sufficient randomness, especially at boot.
  • "This is only a theoretical risk." — Large-scale internet scans have repeatedly found real devices with shared or weak keys traceable to exactly this issue.

16. Glossary

TRNG
True Random Number Generator — hardware that harvests physical entropy sources to produce genuinely unpredictable output.
PRNG
Pseudo-Random Number Generator — a deterministic algorithm that expands a seed into a longer, statistically random-looking stream.
Entropy starvation
A condition where insufficient randomness has accumulated to safely generate cryptographic material.

17. Self-Assessment

1. What is 'boot-time entropy starvation'?

If keys are generated too early in boot, before sufficient entropy has accumulated, the resulting 'random' values can be predictable or correlated across devices.
