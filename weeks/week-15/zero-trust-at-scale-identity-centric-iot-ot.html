Zero Trust at Scale & Identity-Centric Architecture for IoT/OT

Extend zero-trust architecture patterns to agentless OT assets.

35 min read Level: MS foundation → advanced Status: Full lesson

1. Introduction

Week 7 introduced agentless zero trust for individual IoT segments. This lesson scales that same idea across an entire mixed IT/OT estate — an environment where "verify explicitly, assume breach" has to work for everything from a modern cloud workload to a decades-old PLC that will never run any agent at all.

2. Learning Outcomes

By the end of this lesson you will be able to:

  • Extend zero-trust architecture patterns to agentless OT assets.
  • Design identity-centric segmentation for a mixed IT/OT estate.

3. Prerequisites

Week 0 foundations, plus Weeks 0–14 of this course.

4. Core Concepts

Zero trust for agentless assets at scale means every enforcement decision has to happen at a point other than the asset itself — a network policy enforcement point, a broker/gateway (Week 7), or an identity-aware proxy — since a huge fraction of OT assets, by design or by age, will never run a zero-trust agent.

Identity-centric segmentation shifts the segmentation logic from "which network is this device on" (Week 7's VLAN-based approach) to "what identity does this device or communication present, and is that identity authorized for this specific action" — a more granular, more portable model, particularly valuable as OT/IT boundaries blur through cloud integration and remote access needs.

Policy enforcement points (PEPs) in an OT network need to be placed deliberately at the Purdue model's conduits (previous lesson), since that's where identity-based policy decisions can actually be enforced without requiring every Level 0/1 asset to participate directly in the zero-trust architecture.

7. Mathematical / Formal Foundations

No formula — instead, a PEP-coverage exercise: for every Purdue-model conduit in your architecture (previous lesson's audit), confirm a policy enforcement point actually exists there. A conduit without a PEP is a zero-trust architecture gap, regardless of how well other parts of the estate are covered.

8. Practical Examples

Worked example: a remote engineer needs occasional access to a Level 2 SCADA server for maintenance. Rather than granting broad, standing VPN access to the entire OT network segment (Week 7's coarser model), an identity-centric approach grants a time-boxed, identity-verified session scoped specifically to that one server, through a policy enforcement point that logs and can immediately revoke the access — without requiring any agent on the SCADA server itself.

10. Security Perspective

Identity-centric segmentation's real advantage over pure network segmentation is granularity and auditability — a security review can answer "who accessed this specific asset and why" far more precisely than "what could theoretically reach this VLAN," which matters enormously during incident investigation (Week 12).

11. Industry Perspective

OT security vendors increasingly offer identity-aware access brokers specifically designed to sit at IT/OT conduits, providing zero-trust-style access control for legacy assets that will never support a native agent — a maturing product category responding directly to this architectural need.

12. Research Perspective

NIST's zero-trust architecture guidance (SP 800-207, referenced in Week 7) explicitly addresses legacy and agentless asset scenarios, providing a formal basis for the enforcement-point placement strategy this lesson describes, rather than leaving it as an ad hoc industry practice.

13. Case Study

Organizations that have implemented identity-centric access brokering for OT maintenance access have reported significantly improved audit trails and faster incident scoping compared to prior broad, standing VPN access models — directly validating the granularity benefit this lesson emphasizes.

14. Common Misconceptions

  • "Zero trust requires every asset to run an agent." — Agentless assets can be covered through well-placed policy enforcement points at network conduits.
  • "Identity-centric segmentation replaces the need for Purdue model network segmentation." — It builds on and adds granularity to network segmentation, typically enforced at the same conduit points.
  • "Broad, standing remote access is acceptable if the user's identity was verified once at login." — Identity-centric zero trust favors time-boxed, scoped access with continuous verification, not one-time login granting broad standing access.

16. Glossary

Policy enforcement point (PEP)
A network location where access control decisions based on identity and policy are actually enforced.
Identity-centric segmentation
A security model that controls access based on verified identity and authorization rather than solely on network location.

17. Self-Assessment

1. How can zero-trust principles be applied to legacy OT assets that cannot run a security agent?

Zero-trust enforcement can be shifted to a policy enforcement point at a network conduit or gateway, allowing identity-based access control even for assets that will never run a native agent.
