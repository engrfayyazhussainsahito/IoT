4. Core Concepts

The Purdue model organizes industrial networks into hierarchical levels: Level 0 (physical process — sensors, actuators), Level 1 (basic control — PLCs, RTUs), Level 2 (supervisory control — HMIs, SCADA servers), Level 3 (site operations), Level 4/5 (business/enterprise IT). Security zones and conduits (IEC 62443's terminology) are typically drawn along these level boundaries, with strict, monitored traffic control at each conduit — a large-scale, formalized version of Week 7's segmentation principles.

PLCs/RTUs (Programmable Logic Controllers / Remote Terminal Units) execute the actual control logic at Level 1 — their compromise means direct manipulation of physical process behavior, making them among the highest-consequence targets in the entire architecture.

Protocol security posture: Modbus has no built-in authentication or encryption at all — any device that can reach a Modbus-speaking controller can typically issue commands to it. DNP3 added optional Secure Authentication extensions, but adoption is inconsistent across real deployments. OPC-UA was designed with security more centrally in mind, supporting authentication and encryption natively, though correct configuration (not just capability) still determines actual deployment security.

7. Mathematical / Formal Foundations

No formula — instead, a protocol-risk-inheritance principle: a Modbus-speaking device inherits zero built-in protection against command spoofing by design — any security for that specific link must come entirely from network-layer controls (segmentation, allow-listing) since the protocol itself provides none.

8. Practical Examples

Worked example: a Level 1 PLC speaking unauthenticated Modbus is reachable from a Level 3 site-operations workstation due to a missing conduit control between levels. Any compromise at Level 3 (a phishing-compromised workstation, for instance) can now issue direct, unauthenticated Modbus commands to the PLC — illustrating why the Purdue model's level boundaries need to be actual, enforced network controls, not just a conceptual diagram.

10. Security Perspective

Modbus's complete lack of built-in security isn't a bug to be patched — it's a decades-old protocol design assumption (a fully trusted, physically isolated network) that no longer holds in IT/OT-converged environments, meaning all of its security has to come from the network architecture around it.

11. Industry Perspective

Newer industrial protocol deployments increasingly favor OPC-UA specifically for its native security capabilities, but the enormous installed base of Modbus and legacy DNP3 devices means network-layer compensating controls remain essential for the foreseeable future, not a temporary bridge.

12. Research Perspective

ICS security research continues to study real-world Purdue model deployments, consistently finding conceptual level separation that doesn't match actual enforced network controls — a gap between architecture diagrams and operational reality that this lesson's audit checklist is designed to catch.

13. Case Study

Multiple publicly documented industrial incidents (including well-known ICS-targeting malware campaigns) have exploited exactly this gap: a Purdue model diagram showing clean level separation, while actual network configuration allowed unauthenticated Modbus or DNP3 traffic to cross level boundaries unimpeded.

14. Common Misconceptions

  • "A Purdue model diagram documenting level separation means that separation is actually enforced." — Many real deployments have conceptual separation that isn't matched by actual network controls.
  • "Modbus's lack of authentication is an oversight that should be patched at the protocol level." — It's an assumption from its original trusted-network design era; security must come from network architecture instead.
  • "OPC-UA is inherently secure because it supports encryption and authentication." — Support for these features doesn't guarantee they're actually enabled and correctly configured in a given deployment.

16. Glossary

Purdue model
A reference architecture dividing industrial control networks into hierarchical levels (0-5) by function and trust.
PLC
Programmable Logic Controller — a ruggedized industrial computer executing control logic for physical processes.
Zones and conduits
IEC 62443 terminology for network segments (zones) and the controlled connections between them (conduits).

17. Self-Assessment

1. Why does Modbus provide essentially no protection against a device issuing unauthorized commands to a controller?

Modbus was designed decades ago assuming a fully trusted, isolated network — it has no built-in authentication or encryption at all, meaning any device that can reach a Modbus controller can typically issue it commands.
