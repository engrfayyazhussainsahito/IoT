Network Segmentation & Zero Trust for IoT/OT Networks

Design VLAN/segment boundaries for a mixed IT/IoT/OT network.

35 min read Level: MS foundation → advanced Status: Full lesson

1. Introduction

If a device can't run a traditional security agent, can't be patched promptly, and might have unknown vulnerabilities baked in from manufacturing, the network around it has to carry more of the security burden than it would for a modern laptop. Segmentation and zero-trust design are how that burden gets distributed.

2. Learning Outcomes

By the end of this lesson you will be able to:

  • Design VLAN/segment boundaries for a mixed IT/IoT/OT network.
  • Apply zero-trust principles to devices that can't run an agent.

3. Prerequisites

Week 0 foundations, plus Weeks 0–6 of this course.

4. Core Concepts

IoT VLANs and micro-segmentation: placing IoT/OT devices on network segments isolated from corporate IT traffic limits the blast radius if any single device is compromised — a compromised smart thermostat shouldn't have a network path to a finance department's file server.

Agentless zero trust adapts zero-trust principles (verify explicitly, least privilege, assume breach) to devices that can't run a software agent: verification happens at the network layer instead — via switch port authentication (802.1X), network access control (NAC) fingerprinting device behavior, or a gateway that mediates every connection on the device's behalf.

East-west traffic control — restricting device-to-device communication within a segment, not just segment-to-segment — matters because many IoT compromises spread laterally between devices on the same "trusted" network segment once one device is breached, exactly the pattern Mirai-class botnets (Week 9) exploit.

7. Mathematical / Formal Foundations

No formula — instead, a lateral-movement risk estimate: in a flat network with N devices and no east-west restriction, a single compromised device has a direct network path to N-1 others. With device-to-device isolation and only gateway-mediated communication, that same compromise has a direct path to effectively zero peer devices.

8. Practical Examples

Worked example: a building's IoT VLAN allows all devices to communicate freely with each other by default (a common misconfiguration). One compromised camera can now directly scan and attempt exploitation against every other device on that VLAN. Adding device-to-device isolation, with only gateway-mediated traffic permitted, reduces this to a single compromised device with no direct lateral path.

9. Code / Worked Example

SEGMENTATION AUDIT CHECKLIST
[ ] IoT/OT devices are on VLANs separate from corporate IT traffic
[ ] Default-deny rules exist between IoT VLAN and corporate VLAN,
    with only specific, justified exceptions allowed
[ ] Device-to-device (east-west) traffic within the IoT VLAN is
    restricted by default, not implicitly trusted
[ ] Devices that can't run an agent are verified via network-layer
    mechanisms (802.1X, NAC fingerprinting) rather than left unverified
[ ] Gateway mediates and logs cross-segment traffic for visibility

10. Security Perspective

Network segmentation is one of the most effective compensating controls available for a device fleet that inherently can't be fully trusted individually — it doesn't fix any given device's vulnerabilities, but it dramatically limits what a successful compromise can reach next.

11. Industry Perspective

Building-management and industrial-network vendors increasingly ship segmentation as a default-on configuration recommendation rather than an advanced/optional setting, reflecting how consistently flat-network designs have contributed to real incidents.

12. Research Perspective

Zero-trust architecture research (NIST SP 800-207) explicitly addresses agentless and legacy-device scenarios, providing a formal framework for exactly the network-layer verification approach this lesson describes.

13. Case Study

Numerous documented building-automation and industrial incidents follow the same pattern: initial compromise of one internet-facing or poorly secured device, followed by unrestricted lateral movement across a flat network to reach higher-value targets — a pattern segmentation specifically breaks.

14. Common Misconceptions

  • "Putting IoT devices on a separate VLAN is sufficient on its own." — Without east-west restriction within that VLAN, lateral movement between IoT devices themselves remains possible.
  • "Zero trust requires every device to run an agent." — Agentless approaches using network-layer verification are a core, well-established part of zero-trust architecture for exactly this reason.
  • "Segmentation is a one-time network setup task." — Segmentation policies need ongoing review as new devices and use cases are added to a network.

16. Glossary

Micro-segmentation
Fine-grained network segmentation restricting traffic even between devices within the same broader network zone.
East-west traffic
Network traffic between devices within the same segment or tier, as opposed to north-south traffic between tiers.
NAC
Network Access Control — systems that verify and control device access to a network, often via fingerprinting or authentication at the network layer.

17. Self-Assessment

1. Why is 'east-west' (device-to-device) traffic control important in addition to VLAN segmentation from corporate IT?

VLAN segmentation alone limits IoT-to-corporate traffic, but without east-west restriction, devices within the IoT segment can still freely attack each other if one is compromised.
