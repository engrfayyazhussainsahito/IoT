IR From First Principles for Cyber-Physical Incidents

Adapt the IR lifecycle to incidents with physical-world consequences.

35 min read Level: MS foundation → advanced Status: Full lesson

1. Introduction

Week 11 built the detection and triage layer. This lesson picks up the moment triage confirms a genuine incident — and asks how the standard IR lifecycle needs to bend, without breaking, when the system under attack can also hurt someone.

2. Learning Outcomes

By the end of this lesson you will be able to:

  • Adapt the IR lifecycle to incidents with physical-world consequences.
  • Coordinate security response with safety/operations teams during an incident.

3. Prerequisites

Week 0 foundations, plus Weeks 0–11 of this course.

4. Core Concepts

The classic IR lifecycle — preparation, identification, containment, eradication, recovery, lessons learned — still applies, but two adaptations run through every phase in a cyber-physical context:

  • Safety-first decision gates: at each phase, before taking any action, the question isn't just "does this help contain/eradicate the threat" but "could this action itself create an unsafe physical condition" — directly extending Week 11's change-control interlock principle from detection into full incident response.
  • Dual command structures: a CPS incident often needs two coordinated command chains running in parallel — a security incident commander making cyber-response decisions, and an operations/safety incident commander making physical-process decisions — with a defined protocol for reconciling disagreements between them rather than either one unilaterally overriding the other.

Getting the command-structure question wrong is a a common failure pattern: either security defers entirely to operations (leaving the actual compromise unaddressed) or operations defers entirely to security (risking an unsafe response action) — neither extreme reflects the joint expertise a CPS incident actually requires.

7. Mathematical / Formal Foundations

No formula — instead, a phase-by-phase safety-gate exercise: for each of the six classic IR phases, write one sentence describing what a "safety-first" version of that phase's typical action would look like for your specific environment. A phase where you can't complete this sentence is a gap in your CPS IR plan.

8. Practical Examples

Worked example: during containment, a security team's default instinct is to immediately cut network access to a suspected-compromised industrial controller. The operations commander flags that this controller is mid-cycle in a process that requires a controlled shutdown sequence, not an abrupt cutoff. The joint decision gate produces a modified containment action — network isolation staged to align with a safe shutdown sequence — that neither command chain would have designed alone.

10. Security Perspective

A security team operating in isolation during a CPS incident, however well-intentioned, is structurally missing half the information needed to make a safe decision — this isn't a knock on security expertise, it's a recognition that physical-process knowledge is a distinct, necessary input that dual command structures are designed to guarantee gets heard.

11. Industry Perspective

Mature industrial organizations increasingly run joint security/operations incident response drills specifically to build the working relationship and communication protocols before a real incident, rather than attempting to establish dual command coordination for the first time under live pressure.

12. Research Perspective

ICS incident response frameworks (developed further in Week 15) formalize dual command and safety-gate concepts as explicit, named practices rather than leaving them to be improvised during an active incident — a maturation reflected in updated national critical-infrastructure IR guidance.

13. Case Study

Documented industrial incidents have shown cases where security-driven containment actions, taken without operations input, caused unplanned process disruptions beyond what the original security event itself would have caused — the exact failure mode this lesson's dual command structure is designed to prevent.

14. Common Misconceptions

  • "The standard IR lifecycle doesn't apply to CPS incidents at all." — The lifecycle's phases still apply; what changes is the safety-first review layered into each phase's decisions.
  • "Security should always have final authority during an incident, since it's a security event." — Physical-process consequences require operations/safety input as a coordinate authority, not a subordinate one.
  • "Dual command structures slow down response too much to be practical." — A pre-established joint decision protocol, practiced in advance via drills, can operate quickly rather than introducing unplanned delay.

16. Glossary

Dual command structure
An incident response coordination model where security and operations/safety incident commanders jointly review decisions with physical-process implications.
Safety-first decision gate
A required review step assessing whether a proposed incident response action could itself create an unsafe physical condition.

17. Self-Assessment

1. What is the main purpose of a 'dual command structure' in cyber-physical incident response?

Dual command ensures that response decisions with potential physical consequences are reviewed jointly by security and operations/safety expertise, preventing either domain from acting on incomplete information.
