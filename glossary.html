Glossary

Every term defined across the course, in one searchable page.

A/B (dual-bank) partitioning
An update scheme where new firmware is written to an inactive partition and only activated after verification.
A/B partitioning
A dual-bank update scheme where updates write to an inactive partition before switching over.
ABAC
Attribute-Based Access Control — permissions computed dynamically from attributes like device type or context.
Abuse case
A structured description of how an actor could misuse a system feature to violate a security property, paired with a functional requirement.
Actionable remediation
Specific, implementable guidance that allows an engineer to directly address a security finding without needing additional clarification.
Adversarial input
A specially crafted input designed to cause a machine learning model to misclassify or behave incorrectly.
AEAD
Authenticated Encryption with Associated Data — a cipher mode providing both confidentiality and integrity in one operation.
Alert fatigue
Desensitization to security alerts caused by excessive false-positive volume, risking missed genuine incidents.
Anchor event
A known event with a reliable timestamp used to calibrate and correct timestamps across multiple evidence sources.
Anti-rollback protection
A mechanism preventing installation of firmware older than the currently installed version, using a monotonic version counter.
ASan / UBSan
AddressSanitizer and UndefinedBehaviorSanitizer — compiler instrumentation that detects memory errors and undefined behavior at runtime.
Ascon
The algorithm family selected by NIST's Lightweight Cryptography standardization project.
ASLR
Address Space Layout Randomization — a mitigation that randomizes memory addresses to make exploitation harder, requiring an MMU.
Attack surface
The complete set of points where an unauthorized actor could attempt to enter or extract data from a system.
Attack surface mapping
The process of identifying and documenting all potential points of entry or interaction with a target system.
Authorization boundary
The explicit, written scope of systems and actions a researcher is permitted to test.
Beacon drift
A deviation in a device's regular check-in or communication interval from its established baseline.
Bench VLAN
An isolated network segment used for hardware/firmware testing, kept separate from production and home networks.
Boot ROM
Immutable code burned into silicon at manufacturing time; the first and most trusted link in a device's boot chain.
Bootstrap credential
A shared or initial credential used to enroll a device into a cloud platform during first-time provisioning.
Botnet
A network of compromised devices controlled collectively, often for coordinated attacks like DDoS.
Buffer overflow
A bug where data written to a buffer exceeds its allocated size, corrupting adjacent memory.
Canary rollout
A staged deployment strategy that applies a change to a small subset of a fleet before wider release.
Capability (security)
An unforgeable token or reference that directly grants the ability to perform a specific action.
CERT/CC
A coordination center that can help route vulnerability reports when a vendor has no direct security contact.
Change-control interlock
A requirement for engineering or safety sign-off before a security response action is taken against an OT asset.
Charter
A document establishing a project's scenario, scope, constraints, and success criteria.
CIA triad
Confidentiality, Integrity, Availability — the classical model of information security goals.
Clock drift
The gradual divergence of a device's internal clock from accurate/reference time.
CoAP
Constrained Application Protocol — a lightweight, REST-like protocol designed for constrained devices, typically secured with DTLS.
Cohort baselining
Establishing expected-normal behavior patterns for a group of similar devices, used to detect meaningful deviations at fleet scale.
Command and control (C2)
Infrastructure used by an attacker to communicate with and direct compromised devices.
Configuration drift
The divergence of a live system's actual configuration from its intended, reviewed, or version-controlled state.
Constant-time implementation
Code written so its execution time does not depend on secret data, preventing timing side-channel leaks.
Containment ladder
A ranked set of containment actions from least to most operationally disruptive, matched to the severity of a confirmed compromise.
Control plane
The path along which commands and configuration flow toward a device.
Control-flow integrity (CFI)
A set of techniques that restrict a program's execution to a set of legitimate control-flow paths, mitigating exploitation of memory-corruption bugs.
CPS (Cyber-Physical System)
A system where computation directly senses or affects the physical world.
Crash triage
The process of reproducing, minimizing, and root-causing a bug discovered by fuzzing to assess its severity.
Credential lifecycle
The full set of stages a credential goes through: issuance, rotation, and eventual revocation or expiration.
Crypto agility
The ability to swap cryptographic algorithms or key sizes without requiring a full hardware or architecture redesign.
CVD
Coordinated Vulnerability Disclosure — a process of privately notifying a vendor before public disclosure.
Data minimization
The practice of collecting, processing, and retaining only the minimum data necessary for a given purpose.
Data plane
The path along which telemetry and sensor data flow away from a device.
Debug lockout
A mechanism intended to prevent unauthorized use of a device's debug interfaces after manufacturing.
Destructive testing
A testing technique that irreversibly damages or alters the physical device under test.
Detection-as-code
Managing security detection rules as version-controlled, tested code rather than manual configuration.
Device certificate
An X.509 certificate binding a public key to a specific device's identity, signed by a manufacturer or trusted CA.
Device health attestation
A cryptographically verifiable report of a device's current state, such as firmware version or secure-boot status.
Device registry
The authoritative cloud-side record of which devices exist in a fleet and their expected state.
Digital twin
A cloud-side representation of a physical device's state, used for monitoring and control even when offline.
Digital twin / device shadow
A cloud-side representation of a device's expected or last-known state, usable even when the device is offline.
DTLS
Datagram Transport Layer Security — an adaptation of TLS for UDP-based protocols.
Dual command structure
An incident response coordination model where security and operations/safety incident commanders jointly review decisions with physical-process implications.
Duty cycle
The fraction of time a device is permitted or able to transmit, often regulatory or power-driven.
East-west traffic
Network traffic between devices within the same segment or tier, as opposed to north-south traffic between tiers.
ECC
Elliptic Curve Cryptography — public-key cryptography offering strong security at smaller key sizes than RSA.
Edge computing
Processing data closer to where it is generated (e.g., near IoT devices) rather than in a centralized cloud data center.
Emergency stop procedure
A pre-agreed, rehearsed method for immediately halting a security testing engagement if unsafe conditions arise.
Entropy starvation
A condition where insufficient randomness has accumulated to safely generate cryptographic material.
ETSI EN 303 645
A European baseline security standard for consumer IoT devices.
Evidence appendix
A supporting section of an assessment report showing the reasoning and artifacts behind each finding.
Evidence sufficiency
The minimum level of demonstrated impact needed to credibly establish a security finding's real-world risk.
Executive brief
A concise, non-technical document summarizing risk, business impact, and recommended actions for leadership decision-making.
Executive summary
A concise, non-technical summary of an assessment's key findings and recommendations for leadership.
Fallback behavior
A system's defined response to a loss of connectivity or other degraded operating condition.
Fault injection
Deliberately inducing a hardware fault (voltage glitch, clock glitch, laser pulse) to corrupt execution at a targeted moment.
Fault vs. attack triage
The process of distinguishing benign device malfunctions from genuinely malicious activity during initial alert investigation.
Firmware
Low-level software embedded directly on a device's hardware, often with limited or no update mechanism.
Fleet-scale assessment
A security assessment methodology applied across an entire portfolio of products or deployments, rather than a single asset.
Fleet-scoped IAM policy
An access control policy restricting a device's cloud permissions to only its own resources, not the broader fleet.
FMEA
Failure Mode and Effects Analysis — a safety-engineering method for systematically identifying failure consequences.
Fuse (hardware)
A one-time-programmable bit in silicon, often used to permanently store configuration such as key hashes or security enforcement flags.
Fuzzing
Automated testing that feeds large volumes of generated, often malformed input to a program to discover crashes or bugs.
Gateway
A device that bridges a constrained IoT network to IP-based networks, often performing protocol translation.
GATT
Generic Attribute Profile — the BLE specification defining how services and data are exposed and accessed.
GRC
Governance, Risk, and Compliance — the specialization focused on policy, regulation, and assurance for connected products.
Hamming distance (PUF context)
The number of differing bits between two PUF responses, used to measure uniqueness and reliability.
Hardening baseline
A documented, versioned set of security configuration requirements applied consistently across a product's releases.
Hardware crypto accelerator
A dedicated hardware block that performs cryptographic operations (e.g., AES, SHA) far more efficiently than general-purpose software.
HelloVerifyRequest
A DTLS handshake message using a cookie to mitigate denial-of-service amplification attacks.
High-water-mark stack usage
The maximum stack depth actually reached by a task during execution, often measured via stack-painting techniques.
Hot/warm/cold storage tiers
A tiered data retention strategy balancing fast access to recent data against lower-cost long-term storage.
HSM
Hardware Security Module — a high-assurance device for managing and protecting cryptographic keys, often used at cloud or backend scale.
Hybrid cryptography
Using both a classical and a post-quantum algorithm together during a transition period, for defense in depth.
Identity-centric segmentation
A security model that controls access based on verified identity and authorization rather than solely on network location.
Infrastructure as Code (IaC)
Managing and provisioning infrastructure through version-controlled, machine-readable configuration files rather than manual processes.
IOC (Indicator of Compromise)
Observable evidence suggesting a system has been compromised.
IoT (Internet of Things)
Networked physical devices — sensors, actuators, controllers — that exchange data, often with cloud or gateway infrastructure.
IR drill
A simulated exercise walking through the full incident response lifecycle for training or assessment purposes.
ISR
Interrupt Service Routine — code that runs in response to a hardware interrupt, outside normal task scheduling.
IT/OT convergence
The increasing interconnection between information technology and operational technology systems, which can propagate IT incidents into OT consequences.
JTAG
Joint Test Action Group interface — a standard hardware debug and boundary-scan interface used for programming and debugging chips.
K3s
A lightweight Kubernetes distribution designed for resource-constrained and edge environments.
Lessons-learned feedback loop
The practice of feeding incident findings back into design requirements and abuse-case libraries to prevent recurrence.
Linker script
A file specifying how code and data sections are laid out in a target's memory address space.
Log normalization
The process of translating raw, protocol-specific log data into a standardized, human-readable and correlatable format.
Logic analyzer
A tool that captures and decodes digital signals on multiple pins simultaneously, used to identify bus protocols.
LPWAN
Low-Power Wide-Area Network — long-range, low-bandwidth radio designed for battery-powered sensors (e.g., LoRaWAN, NB-IoT).
Micro-segmentation
Fine-grained network segmentation restricting traffic even between devices within the same broader network zone.
MicroPython
A lean implementation of Python 3 designed to run directly on microcontrollers.
Minimal telemetry footprint
A small, carefully selected set of security-relevant signals designed to fit within a constrained device's power/bandwidth budget.
MISRA C
An industry coding standard restricting C to a safer subset, widely used in automotive and industrial embedded development.
Model extraction
An attack that attempts to reconstruct a deployed machine learning model's parameters or behavior through repeated querying.
MPU
Memory Protection Unit — hardware that can restrict which memory regions a task may access, without full virtual memory.
MQTT topic ACL
An access control rule restricting which MQTT topics a specific client may publish to or subscribe from.
Mutual TLS (mTLS)
A TLS handshake variant where both client and server present certificates, authenticating each other.
NAC
Network Access Control — systems that verify and control device access to a network, often via fingerprinting or authentication at the network layer.
Network-based detection
Security monitoring performed by observing a device's traffic and behavior from the network's external perspective.
Non-destructive acquisition
A forensic data-extraction method that does not permanently alter or disable the device being examined.
Nonce
A number used once per encryption operation with a given key; reuse can break many AEAD modes' security guarantees.
NX/DEP
No-eXecute / Data Execution Prevention — marking memory regions as non-executable to prevent injected code from running.
On-device detection
Security monitoring performed using signals a device can observe about its own internal state.
Operational window
A scheduled period during which testing-induced disruption to a physical process is acceptable.
OT (Operational Technology)
Hardware and software that monitors or controls physical processes, common in industrial environments.
OT-aware SOC
A security operations function whose priorities, data sources, and playbooks are adapted for operational technology's safety and availability requirements.
OTA update
Over-The-Air update — a firmware or software update delivered wirelessly to a deployed device.
OTAA / ABP
LoRaWAN activation methods — Over-The-Air Activation (dynamic session keys) versus Activation By Personalization (static, unrotated keys).
Overlay filesystem
A small writable layer mounted over a read-only base image, used for configuration and logs.
Patch adoption rate
The percentage of a device fleet that has successfully received and applied a given update.
PLC
Programmable Logic Controller — a ruggedized industrial computer executing control logic for physical processes.
Policy enforcement point (PEP)
A network location where access control decisions based on identity and policy are actually enforced.
Portfolio density
The ratio of depth/reasoning to raw quantity in a collection of portfolio artifacts.
Post-quantum cryptography (PQC)
Cryptographic algorithms designed to remain secure against attacks from large-scale quantum computers.
Pre-shared key (PSK)
A symmetric key established out-of-band and shared between communicating parties before a session begins.
Privacy-by-design
An approach that embeds privacy considerations into a system's architecture from the earliest design stages.
PRNG
Pseudo-Random Number Generator — a deterministic algorithm that expands a seed into a longer, statistically random-looking stream.
Proof of concept (PoC)
A minimal demonstration establishing that a vulnerability is real and exploitable, without necessarily building a fully weaponized exploit.
Provenance
Verifiable information about a component's origin and manufacturing history, used to detect counterfeit or substituted parts.
PUF
Physically Unclonable Function — a hardware mechanism deriving unique identity from manufacturing variation.
Purdue model
A reference architecture dividing industrial control networks into hierarchical levels (0-5) by function and trust.
Purple team
A collaborative practice where offensive (red team) findings are directly shared with defensive (blue team) staff to improve detection and response.
pyserial
A Python library for reading and writing to serial (UART) ports.
Race condition
A bug where the outcome depends on the relative timing of concurrent operations.
RACI
A framework (Responsible, Accountable, Consulted, Informed) for clarifying roles in a decision-making process.
RBAC
Role-Based Access Control — permissions attached to roles, assigned to entities.
Re-provisioning
Reissuing a device's credentials or identity material as a remediation step, without necessarily replacing its firmware.
Recovery time objective (RTO)
The targeted duration within which a system or process must be restored after a disruption.
Relay attack
An attack using two colluding devices to extend the effective range of a short-range signal, defeating proximity-based security assumptions.
Resilience (security)
A system's capacity to detect, respond to, and recover from security incidents, complementing but not replacing prevention.
Responsible research scope
The practice of limiting testing to systems you own or have explicit written permission to test.
RF footprint
The set of frequencies, protocols, and communication patterns a device actually uses in practice.
Risk register
A structured record of identified risks, their assessment, and corresponding mitigation status, often maintained at a portfolio level.
Risk tier
A categorization of a product or asset's risk level, used to determine appropriate assurance and control requirements.
Root of trust
The foundational component in a system that must be trusted unconditionally, since nothing else verifies it.
Rules of Engagement (RoE)
The documented scope, boundaries, and authorized techniques for a security testing engagement.
Safe automation guardrail
A constraint ensuring automated security responses cannot bypass necessary safety or change-control review, especially for OT assets.
Safety (as a security property)
Freedom from conditions that could cause physical harm to people, property, or the environment.
Safety-first decision gate
A required review step assessing whether a proposed incident response action could itself create an unsafe physical condition.
Safety-security co-engineering
An approach that analyzes safety and security risks together rather than in separate silos.
SBOM
Software Bill of Materials — an inventory of components in a software or firmware build.
Scope creep
Unplanned expansion of a project's work beyond its originally agreed boundaries.
SDR (Software-Defined Radio)
A radio receiver/transmitter that digitizes signals for flexible, software-based processing rather than relying on fixed, protocol-specific hardware.
Secure boot chain
A sequence of boot stages where each verifies a cryptographic signature on the next before executing it.
Secure default
A configuration a product ships with by default that favors security, requiring deliberate action to weaken rather than to enable.
Secure element
A physically separate, tamper-resistant chip dedicated to secure key storage and cryptographic operations.
Secure SDLC
Software Development Lifecycle with security activities integrated into each phase, from requirements through response.
Secure-by-design
A product development philosophy where manufacturers build security in as a default, owned outcome from the earliest design stages.
Security governance
The structures and processes by which an organization makes and is accountable for security-related decisions.
security.txt
A standardized file vendors can publish to indicate how to report security issues.
Service minimization
The practice of disabling or removing any running service not strictly required for a device's production function.
Session resumption
Reusing an abbreviated handshake to re-establish a secure session without repeating the full asymmetric handshake.
Side-channel attack
An attack that extracts secret information from a system's physical characteristics (timing, power, electromagnetic emissions) rather than breaking its logic or cryptography directly.
Site-to-site VPN
An encrypted tunnel connecting two networks (e.g., a remote gateway and a central platform) over an untrusted network like the public internet.
SOC maturity model
A structured framework for assessing and progressing a security operations program's capabilities over defined stages.
SSVC
Stakeholder-Specific Vulnerability Categorization — a prioritization framework incorporating mission and safety impact.
Stack canary
A known sentinel value placed near a buffer, checked before function return to detect stack-based buffer overflows.
STRIDE
A threat-modeling mnemonic: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.
Supply-chain risk
Risk introduced into a product through the security posture or practices of its component suppliers.
Support tail
The period during which a shipped product continues to receive security updates after release.
Tabletop exercise
A discussion-based simulation of an incident scenario used to test and improve response plans and coordination.
Tamper-evident
Design that ensures tampering leaves visible evidence, without necessarily preventing the tampering itself.
Tamper-resistant
Design that actively raises the cost or difficulty of accessing or modifying a device's internals.
TEE (Trusted Execution Environment)
A hardware-enforced isolated execution environment within a processor, separating trusted operations from the main OS.
Test point
An exposed pad or via on a PCB intended for manufacturing test or debug access.
Threat
A potential source of harm, such as an actor, event, or condition.
Threat hunting
Proactive, hypothesis-driven investigation for signs of compromise, independent of triggered alerts.
TRNG
True Random Number Generator — hardware that harvests physical entropy sources to produce genuinely unpredictable output.
Trust boundary
A point in a system where data or control crosses between components with different levels of trust.
UART
Universal Asynchronous Receiver/Transmitter — a simple two-wire serial interface, commonly used for debug consoles.
UK PSTI Act
UK legislation (Product Security and Telecommunications Infrastructure Act) imposing baseline IoT security requirements.
Undefined behavior (UB)
Program behavior for which the C standard imposes no requirements, permitting any outcome including compiler optimization that removes intended logic.
Untrusted input
Any data originating outside a trust boundary that must be validated before use.
Vendored SDK
A chip or platform vendor's library bundled directly into a project's source, often outside normal dependency management.
Volatile evidence
Data that exists only while a device is powered and running, such as RAM contents, lost on power-off or reboot.
Vulnerability
A weakness that could be exploited by a threat to cause harm.
W^X
A memory protection policy where a given memory page is either writable or executable, but never both simultaneously.
Waterfall display
A spectrum-analysis visualization showing signal strength across frequency and time.
Write-blocker
A tool or method ensuring that an acquisition process cannot modify the original evidence source.
Zero trust
A security model that assumes no implicit trust based on network location and verifies every request explicitly.
Zeroization
The active, immediate erasure of sensitive key material upon detection of tampering or compromise.
Zones and conduits
IEC 62443 terminology for network segments (zones) and the controlled connections between them (conduits).
