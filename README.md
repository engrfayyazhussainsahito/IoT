## Overview

IoT & Cyber-Physical Systems Security is an open-access, browser-based educational platform designed to develop a systematic understanding of security across connected devices, embedded computing environments, wireless communication systems, industrial technologies, and cyber-physical infrastructure.

Unlike conventional information security curricula that focus primarily on software, networks, and enterprise systems, this course examines the relationship between digital security and the physical processes controlled by connected technologies.

A compromised smart device, industrial controller, sensor network, or embedded system may affect availability, operational integrity, equipment, or human safety. Accordingly, the curriculum treats safety-aware threat modeling, device identity, secure firmware, hardware trust, network protection, incident response, and operational resilience as interconnected security engineering concerns.

The 17-week learning pathway begins with electronics, embedded operating systems, networking, scripting, and laboratory readiness. It then progresses through cryptography for constrained devices, secure firmware development, memory safety, hardware security, wireless protocols, fleet management, cloud platforms, security operations, digital forensics, authorized hardware testing, industrial security, and emerging technologies.

The course culminates in an integrated capstone in which learners develop and present a security program for a fictional fleet of connected devices.

The platform is implemented using HTML, CSS, and JavaScript and is hosted on GitHub Pages. Its browser-based interface provides structured lessons, diagrams, quizzes, practical exercises, searchable terminology, and learning-progress features.

## Core Technical Domains

### 1. Embedded Systems and Device Foundations

Understand the computing environments that power connected devices and the constraints that influence their security.

Key topics include:

- Microcontrollers and embedded computing.
- Embedded Linux and real-time operating systems.
- Electronics fundamentals and device interfaces.
- Sensors, actuators, and connected-device architectures.
- Python scripting and embedded data analysis.
- Hardware and software dependencies.
- Safe laboratory setup and responsible experimentation.

### 2. Device Identity and Applied Cryptography

Explore how connected devices establish identity, authenticate communication, protect sensitive information, and maintain trust throughout their lifecycle.

Key topics include:

- Device authentication and authorization.
- Cryptographic principles and secure communication.
- Key management and entropy considerations.
- Identity provisioning and credential protection.
- Trust establishment in constrained environments.
- Embedded operating-system hardening.
- Secure device onboarding and lifecycle management.

### 3. Secure Firmware and Software Engineering

Study the security lifecycle of software that operates close to hardware and controls physical processes.

Key topics include:

- Firmware architecture and development.
- Secure coding and dependency management.
- Firmware integrity and verification.
- Secure boot concepts.
- Over-the-air update security.
- Memory safety and vulnerability analysis.
- Fuzzing and defensive testing.
- Security verification across firmware releases.

### 4. Hardware and Physical Security

Examine the interfaces and physical characteristics that distinguish embedded security from conventional application security.

Key topics include:

- Hardware attack surfaces.
- Debug and diagnostic interfaces.
- Secure boot chains and hardware roots of trust.
- Tamper resistance and physical access assumptions.
- Side-channel security fundamentals.
- Board-level and firmware interaction.
- Security implications of hardware lifecycle management.

### 5. IoT and Wireless Network Security

Understand how connected devices communicate and how their communication environments affect security.

Key topics include:

- IoT network architectures.
- Wireless and application-layer protocols.
- Device-to-gateway communication.
- Network segmentation and access control.
- Communication integrity and authentication.
- Monitoring and investigation of network traffic.
- Security implications of constrained networks.

### 6. Fleet, Cloud, and Platform Security

Examine how device security changes when an organization manages hundreds or thousands of deployed devices.

Key topics include:

- Device provisioning and fleet identity.
- Centralized device management.
- Firmware patching and lifecycle control.
- Cloud identity and access management.
- Edge computing and platform integration.
- Secure development and deployment pipelines.
- Telemetry, monitoring, and fleet-wide risk.
- Resilience and recovery planning.

### 7. Security Operations and Digital Forensics

Develop the reasoning required to detect, investigate, and respond to security incidents involving connected and embedded systems.

Key topics include:

- Security telemetry and event analysis.
- Alert triage and detection engineering.
- Incident response and containment.
- Firmware and flash-memory investigation.
- Evidence preservation and chain of custody.
- Recovery and post-incident analysis.
- IoT/OT-specific investigation considerations.

### 8. Industrial and Cyber-Physical Systems Security

Explore the security implications of systems in which software and networks interact with physical processes.

Key topics include:

- Operational technology (OT).
- Industrial control systems (ICS).
- Supervisory Control and Data Acquisition (SCADA).
- Safety-aware threat modeling.
- Availability and operational resilience.
- Segmentation and Zero Trust principles.
- Industrial incident response.
- Secure-by-design engineering for connected infrastructure.

### 9. Governance, Privacy, and Emerging Technologies

Connect technical controls with organizational accountability, regulatory obligations, and emerging security challenges.

Key topics include:

- Security risk assessment.
- Privacy engineering and data protection.
- Supplier and third-party risk.
- Governance and compliance considerations.
- Post-quantum cryptographic readiness.
- Edge AI security.
- Security requirements across the device lifecycle.
- Research directions in IoT and CPS protection.

## Educational Approach

### First-Principles Understanding

Lessons introduce the underlying computing, electronics, networking, and security concepts needed to reason about embedded systems rather than relying exclusively on tool-specific instructions.

### Safety-Aware Security Engineering

The curriculum recognizes that IoT and cyber-physical systems may control physical processes. Security assessments therefore consider safety, availability, operational continuity, and potential physical consequences alongside confidentiality and integrity.

### Practical and Scenario-Based Learning

Worked examples, diagrams, code examples, case studies, quizzes, and laboratory exercises connect abstract principles with realistic security scenarios.

### Full-Lifecycle Perspective

Security is considered across device design, provisioning, deployment, monitoring, patching, incident response, and retirement rather than as a one-time configuration task.

### Research and Industry Context

The course encourages learners to evaluate technical trade-offs, consider operational constraints, document assumptions, and investigate how security mechanisms apply in industrial and embedded environments.

## Intended Audience

This platform is suitable for:

- Undergraduate and graduate students studying Cybersecurity, Computer Science, Electrical Engineering, or related disciplines.
- Security practitioners extending their knowledge into embedded and IoT environments.
- Firmware and embedded software developers learning secure engineering.
- Network and security engineers working with connected devices.
- SOC analysts interested in IoT/OT telemetry and incident investigation.
- Industrial security professionals studying cyber-physical risk.
- Researchers exploring embedded security, hardware trust, and industrial resilience.

The curriculum begins with foundational material but progresses to advanced topics. Learners benefit from basic familiarity with programming, computer networking, and operating systems; Week 0 is designed to establish the required baseline.

## Learning Outcomes

After studying the relevant lessons and completing the associated exercises, learners should be able to:

1. Explain the architecture and security requirements of connected and embedded systems.
2. Identify how physical safety and operational availability influence cyber-physical security decisions.
3. Analyze device identity, access control, cryptographic, and operating-system security mechanisms.
4. Explain secure firmware development, update verification, and embedded vulnerability classes.
5. Identify hardware and wireless attack surfaces and understand appropriate defensive controls.
6. Design device and network hardening strategies for connected environments.
7. Explain the security implications of cloud-connected device fleets and edge computing.
8. Interpret IoT/OT telemetry and outline incident-response and forensic workflows.
9. Apply threat modeling and risk prioritization to a fictional IoT or industrial deployment.
10. Evaluate governance, privacy, supplier risk, and emerging technology considerations.
11. Document security findings and communicate a coherent defense strategy for an IoT/CPS environment.

These are intended learning outcomes. Completing this platform alone does not confer a formal academic qualification or professional certification.

Open `index.html` in a modern web browser.

```bash
python -m http.server 8000
```

## Ethical Use and Laboratory Safety

IoT security research must account for both cybersecurity and physical-world consequences.

- Conduct hardware, firmware, network, and wireless testing only on devices and environments you own or have explicit authorization to assess.
- Use isolated laboratories, virtual environments, and approved training devices.
- Do not interfere with public infrastructure, industrial control systems, medical devices, or other safety-critical systems.
- Conduct RF experiments only within applicable laws, permitted frequencies, and authorized conditions.
- Avoid destructive testing on devices that control real physical processes.
- Protect credentials, device identities, personal data, and sensitive telemetry.
- Preserve forensic evidence and document testing activities responsibly.
- Follow coordinated vulnerability disclosure practices when reporting security weaknesses.
- Apply safe operating procedures and stop an exercise if it creates an unexpected physical or operational risk.

All practical exercises are intended for authorized, controlled, and educational environments. The course does not authorize testing against real systems without permission.

## Capstone: IoT Security Program

The final capstone integrates the course's major technical and organizational themes into a security program for a fictional fleet of connected devices.

A strong capstone submission should document:

1. System architecture and device inventory.
2. Assets, trust boundaries, and attack surfaces.
3. Threat model and risk prioritization.
4. Device identity, firmware, and communication controls.
5. Network segmentation and cloud-platform security.
6. Monitoring, detection, and incident-response procedures.
7. Evidence preservation and recovery planning.
8. Governance, privacy, and third-party risk.
9. Safety implications and operational constraints.
10. Architecture diagrams, justified recommendations, and a final presentation.

The objective is to demonstrate the ability to connect individual security controls into a coherent, safety-aware defense strategy.
